## SUB-PHASE D: ACCESSIBILITY

Run automated accessibility checks on every page touched by this task, then add manual spot-checks for behavior that automation cannot catch.

**Applicability:** Automated axe-core scans require a JS/TS browser runner (Playwright, Cypress, or equivalent). For non-JS stacks without a browser runner, skip the automated scan, do only the manual spot-checks in Step D2, and add `"a11y"` to `skipped_checks[]` in the review-log entry with the reason `"axe-core not applicable to <stack>"`.

### Step D1: Run automated accessibility scan

If the configured stack supports Playwright + `@axe-core/playwright`:
1. Write a temporary accessibility test in the stack's E2E test directory that loads each page touched by the task.
2. Run the test.
3. Clean it up after recording results (or commit it permanently if the project has an a11y test directory).

If the stack uses a different browser runner, use the nearest equivalent accessibility tooling (`cypress-axe`, `pa11y-ci`, `lighthouse --only-categories=accessibility`).

Prefer the canonical project E2E command (e.g., `npm run test:e2e`, `make test-e2e`) where possible so the a11y test runs in the same harness as other E2E checks.

### Step D2: Manual accessibility spot-checks

Things automated scans miss:
- Are interactive elements keyboard-navigable (Tab, Shift+Tab, Enter, Space, Escape)?
- Is the focus order logical and does focus stay visible?
- Do form inputs have visible labels (not just placeholders)?
- Are error messages programmatically associated with their inputs (`aria-describedby`, `aria-invalid`)?
- Are modal dialogs trap-focused and dismissible with Escape?
- Is color contrast sufficient for text on colored backgrounds (WCAG 2.1 AA: 4.5:1 for normal text, 3:1 for large text)?
- Do animations respect `prefers-reduced-motion`?
- Are images decorative or meaningful, and do meaningful ones have non-empty `alt`?

### Step D3: Record accessibility results

List any WCAG 2.1 AA violations found. Fix critical violations (missing labels on form fields, untraversable modal, contrast under 3:1) before moving on. Log serious or moderate violations in the review-log entry with `category: "other"` and a clear `severity`.

If the page touched by this task is internal-only (admin tooling, dev dashboards) and `.agent/spec.md` declares an internal-only audience, contrast and decorative-image findings MAY be downgraded to `nit`. Keyboard-navigation and label findings remain at their original severity even for internal tools.
