## Iteration 1 — evidence-review-status-summary (build_pass)

Feature: Add a compact status summary to the evidence review workflow showing how many
required acceptance criteria are passing, failing, unreviewed, or missing evidence, updating
live as criterion verdicts and selected evidence change.

Approach (per ADR-001 / build-spec build order):
- Derived from existing client-side review state — no persistence, API routes, or duplicated
  verdict state. Classification mirrors calculateReviewVerdict precedence exactly so the summary
  buckets always reconcile with the final verdict.

Files changed:
- lib/evidence-review.ts: added RequiredCriteriaStatusSummary type + pure
  summarizeRequiredCriteria(criteria, states) deriving the four required-criteria buckets.
- app/evidence-review-workflow.tsx: useMemo over criterionStates; new aria-live="polite"
  status-summary section rendered right after the final-verdict section, with stable test IDs
  (status-summary, status-summary-passing/failing/unreviewed/missing-evidence,
  status-summary-required-total, status-summary-state-json).
- app/globals.css: .status-summary / .status-summary-counts styles + responsive collapse,
  matching the existing section/verdict design language.
- lib/evidence-review.test.ts: 6 vitest cases (initial unreviewed, pass→passing, pass-without-
  evidence→missing-evidence, accepted, partition invariant, agreement with calculateReviewVerdict).
- tests/acceptance.spec.ts: Playwright test proving the summary appears on open, carries
  aria-live, and updates on verdict and evidence changes through to the all-passing/accepted state.

Commands run:
- make check / make test  -> vitest 79 passed (9 files); +6 new vs the 73 baseline.
- make build              -> next build compiled + TypeScript check clean.
- make test-e2e (scoped)  -> new "status summary" spec passed; neighbor "ordered evidence review
  workflow" spec passed (no regression). Ran scoped rather than the full Playwright suite (trace+
  video on every test) to keep the iteration bounded; the full suite was not exercised this run.

Notes / risk:

  tests/acceptance.spec.ts) outside the Next build graph; not introduced by this change and not
  failing make check or make build. Left untouched (out of scope for this feature).

## Iteration 2 — evidence-review-blocker-callout (build_pass)

Feature: Add a visible blocker callout beside the final verdict that lists the concrete
reasons the review cannot be accepted, and flips to an accepted-state message once every
required criterion passes with selected evidence.

Approach (per ADR-002 / ADR-003 / build-spec build order item 3):
- Rendered purely from the existing calculateReviewVerdict result (verdict.status +
  verdict.reasons). No new persistence, API routes, or duplicated verdict state — the callout
  consumes the same single source of truth already driving the final-verdict section, so it can
  never disagree with the computed verdict. No new lib helper was needed (the blocked/rejected/
  accepted reason text is already covered by lib/evidence-review.test.ts via calculateReviewVerdict),
  so I did not add padding unit tests that would only restate existing coverage.

Files changed:
- app/evidence-review-workflow.tsx: new aria-live="polite" blocker-callout section inserted
  between the final-verdict and status-summary sections. Blocked/rejected branch renders a
  reason count + verdict.reasons list (stable test IDs blocker-callout, -status, -heading,
  -reason-count, -reason); accepted branch renders the accepted message (blocker-callout-accepted).
  Heading reads "Cannot accept yet" while blocked/rejected and "Ready to accept" when accepted.
- app/globals.css: .blocker-callout styles with status-colored left border
  (blocked=warning, rejected=error, accepted=green), matching the existing .verdict design language.
- tests/acceptance.spec.ts: Playwright test proving the callout is open-only, carries aria-live,
  lists the three initial "no criterion verdict" reasons (blocked), collapses to the single FAIL
  reason (rejected), surfaces the missing-evidence reason (blocked), and flips to the accepted
  message with zero reason items once all criteria pass with evidence.

Commands run:
- make check / make test -> vitest 79 passed (9 files); unchanged baseline (no new lib logic).
- make build              -> next build compiled + TypeScript check clean.
- make test-e2e (scoped)  -> new "blocker callout" spec passed; neighbor "status summary" spec
  passed (no regression from the inserted DOM). Ran scoped (trace+video on every test) to keep
  the iteration bounded; the full Playwright suite was not exercised this run.

Notes / risk:
- next-env.d.ts toggles between .next/types and .next/dev/types depending on whether next dev
  (Playwright webServer) or next build ran last; restored to HEAD and excluded from the commit
  (the prior status-summary commit also excluded it).
- Pre-existing repo-root modifications (agents/codex.md, scripts/codex-exec.mjs) are unrelated
  to this feature and outside the playground; left untouched and not committed.
- Git push intentionally skipped (ULISSE_ALLOW_ENGINE_PUSH=0); local commit only.
- qa_pass left false for the QA agent.
